### 免口令的护栏（重要）

公开写入不是"裸奔"，四条护栏：

1. **限流**（按 IP + 用途，内存计数）：新建角色 10 分钟 40 条、新增关系 60 条、上传立绘 30 张、发公告 20 条；
2. **权限分级**：改/删/回滚仍要共享口令；
3. **全部进版本历史**（`wiki.db`）—— 谁改的、改了什么、什么时候，任何一版都能回滚；
4. **删除类操作前自动备份**数据文件（服务端老逻辑保留）。

| `tools/_netsite/app.js` | 顶栏/首页按钮绑定；深链识别加 `portal`/`edit`（否则首页会盖住门户） |
| `site/*` | 重建产物（全量 273 角色 + 133 张立绘 × 2 档） |

**顺带修掉的真 bug（Python 求值顺序）**：
`st.save(..., kind="char_create" if created["flag"] else "char_update", ...)` —— Python **先算实参再调用**，
而 `created["flag"]` 是 `mutate` 执行时才置位的 → 新建的角色在版本历史里**永远被记成 `char_update`**。
修法：`kind` / `summary` 支持传 `lambda`，在快照那一刻才求值。

**另外修掉的**：`#/portal` 深链打不开（首页 deepLink 正则漏了 `portal`，首页把门户盖住）；
门户切换标签时 `innerHTML` 把表单自己清掉（改成只渲染子容器 `#pnFeed` / `#pnAnn`）。

## 五、部署（**主人说了这轮先不推线上**）

等要上线时，把**前端 + 服务端代码 + 立绘**推上去即可（**别推 `server/data/`**，线上数据是权威的）：

```powershell
# 1) 前端（site\ 已是最新构建：全量 273 角色 + 立绘两档）
scp -r <仓库>\site\* root@<服务器IP>:/opt/trpg-wiki/site/

# 2) 服务端（全量口径 + 免口令新增 + 公告 + 布局账本 + 懒求值修 bug）
scp <仓库>\server\store.py <仓库>\server\edit_api.py root@<服务器IP>:/opt/trpg-wiki/server/

# 3) 重启 + 目录权限（立绘上传要写 site/assets/portraits）
ssh root@<服务器IP> "chown -R www-data:www-data /opt/trpg-wiki/site/assets/portraits /opt/trpg-wiki/server/data && systemctl restart trpg-wiki && systemctl status trpg-wiki --no-pager | head -5"
```

**上线后自检五项**：
1. 首页统计里角色数变成 **273**（不是 ~141）；
2. 随便点一个没立绘的角色 → 显示「未解封」剪影卡（不是破图）；
3. `<http://<服务器IP>:8080/#/portal>` → 三栏都能开，最近改动有记录；
4. 门户里**不输口令**建一个角色 → 刷新后能看到；`#/portal/new` 传一张图 → 档案页出现立绘；
5. 顶栏 `＋` / `☰` 都能点开。
