## 二、重要口径与踩坑（别再犯）

### 生图
1. **`BadZipFile: Bad CRC-32` ≠ 图坏了**：docx 的 zip CRC 写错时 `z.read()` 抛异常但字节完好。
   绕过校验重读 + **PIL 真解码一次**再下结论（知行就是这么被误判的，差点白跑 NAI）。
2. **封面用「角色串」比自写外貌准**（主人指定）：`leaf_(black_souls)` / `faust_(project_moon)`，
   只在上面加强**神态 + 衣服**。但角色串的原生设计可能带库里没有的元素
   （Leaf 自带女仆头饰）→ 用正向 `translucent insect wings, blue hair ribbon` +
   负向 `maid headdress, maid headband, maid apron, nurse cap` 校正。
3. **画师署名**必须在正向串末尾挂 `SIG_KILL`（`-2::signature::, ...`），NEG 压不住。
4. **构图串别写 `simple background`**（整批纯色底）。

### 入库 / 数据
5. **改 `type` / 合并节点 / 改关系端点，都必须同时改补丁**——`store` 去重键是 `(from,to,type)`，
   而 `characters[]` 是「新节点」清单。只改生产库不删补丁 → 下次 `store` 会**重建节点 / 重复加边**。
6. **合并人物要分清「重定向造成的冲突」和「本来就存在的重复」**：
   前者该丢，后者**不许动**（顺手清等于偷偷改数据）。见 `_merge_chars.py` 的实现。
7. **`store` 只能加不能删** → 改数据一律「直接改 JSON + 备份 + 复验」。

### 前端
8. **`.hname` 选择器**：标签挂在 `#labels` 下，**不是** `.hull` 的子元素 → 写 `.hull .hname` 匹配不上，
   div 会退化成静态块全堆在原点。
9. **`pointerdown` 的「可点击元素」白名单要跟上类名**：漏了 `.tile` → pointerdown 走了拖拽分支，
   `setPointerCapture()` 把后续指针事件全截走，**封面六边形点了没反应**。
10. **阵营铭牌的锚点要用「块里卡片的真实位置」算**，不能用「块自身高度 h/2」——
    同一行里矮块与高行共用行中心 `cy`，用 h/2 会让矮块的标签钻到块内部（主人报的「tag 错位」）。
11. **人数徽章别放在六边形内部右上角**——会被 `clip-path` 的斜边裁掉，要放 tile 外层。
12. **重建 `site/` 前必须先停本地服务**（服务 cwd 就在 `site\`，否则 `PermissionError: WinError 32`）。

### 排障纪律（本轮血泪）
13. **截图崩了先看服务活着没**，别急着改代码：
    本轮连续崩十几次，一路二分（去 boot/home → 去 app.js → 去 CSS → 纯 HTML）**全都崩**，
    真相是**上一轮会话中断把后台 job 清了、本地 http 服务早死了**。用 `file://` 一测就正常。
14. **别用 `Stop-Process -Name msedge`**（会误杀主人的浏览器）。按 PID / commandline 精确匹配。
15. **本机内存吃紧**（主人自己的 Edge 有 25+ 进程，可用常在 1.5~2.5 GB）→ 截图用**小视口**；
    headless profile 反复崩坏时清掉 `.tmp\edge-shot-profile`。
16. **`node --check site\app.js`** 能在没有浏览器时抓语法错（本轮抓到 `SQUAD_CAP is not defined`，
    而 Edge 报的是驱动崩溃、**伪装成"截图失败"**）。

**为什么是"覆盖层"而不是直接写库**：既要有 wiki 的即时感，又要守住铁律「生产库改动必须人工过审」。
审核通过只写 D1，前端把 approved 套在 `data.js` 上；生产库靠 `_pull_suggestions.py` 人工同步
（而且 `store` 只支持新增，**删除/改端点必须人工**，所以工具里那类只列清单不执行）。

**架构**：`wrangler.jsonc` 加 `main` + `d1_databases` + `assets.run_worker_first:["/api/*"]`；
新增 `worker/index.js`、`worker/schema.sql`、`tools\_netsite\wiki-boot.js`、`tools\_netsite\wiki.js`。
⚠️ **`build_net_site.py` 原来写死只拷 index/style/app 三个文件** —— 加 wiki.js 时被漏掉，已改成通配。

**三个坑（都值得记）**

1. **`const` 不挂 `window`**：app.js 的 `const CH/S/ADJ` 在 wiki.js 里 `window.CH` 是 `undefined`
   → 「`#/c/<id>` 直达打不开」。解法：app.js 末尾 `window.APP = {CH,S,ADJ,N,CW,CHh}`。
2. **一个不存在的 DOM 会搞垮整个初始化**：`$('#rvAll')` HTML 里没有，`null.addEventListener` 中断了 `wire()`，
   **连首屏路由与 hashchange 监听都没绑上**（现象很迷惑：搜索能用、直达打不开）。解法：`on()` 防御性绑定。
3. **z-index 必须高于首页**：`.search`(120)/`.review`(125) < `.home`(150) → DOM 上 `.on` 已置、断言全绿，
   **用户却什么都看不见**。解法：提到 160/158/165，并给测试补上**遮挡断言**
   （`elementFromPoint` 中心点必须命中自身）—— 光断言 class 是不够的。

**实测**：API 15/15 · 前端本地 17/17、线上 17/17 · 手机端回归仍全绿 · 线上 5 个前端文件 SHA256 与本地一致。

**管理入口**：顶栏 `?` → 帮助面板底部「⚙ 提案箱管理」（或 `#/review`）；口令在 `<凭据文件-未随仓库发布>`

  关系条目「✎ 改 / 🗑 删」· **新页面 `#/tags`**（维度聚合 + 多选 + AND/OR + 直达 `#/tags/维度=值`）·
  搜索吃进 attrs（每个「维度=值」成为可搜可跳的标签条目）· 覆盖层按维度合并 attrs + 关系精确定位 ·
  审核页 diff 支持新内容 · `_pull_suggestions.py` 支持 attrs 与关系改删落盘（**并同步补丁**）。
- **实测**：API 24/24 · UI 本地 33/33 · 线上 32/32 · 手机端零退化 · 线上 232 个资源 0 缺失。

**两个真 bug（同一个病根，本小姐犯了第二次）**：切视图时**只关了部分覆盖层** ——
① 审核页盖住档案页；② **首页盖住深链角色页**（意味着**别人点开分享链接看到的是首页！**）。
病根是「断言只查 DOM 元素存在、不查有没有被遮挡」。已加**遮挡断言**（中心点 `elementFromPoint` 必须命中自身），
并把路由改成「**切视图先清场**」。
> ⚠️ **以后凡是面板类 UI，一定要断言可见性，不能只断言存在。**

**一个操作事故**：`build_net_site.py` 重建要 `rmtree(site)`，而 **`wrangler dev` 正占着 `site/`** →
删到一半 `PermissionError`，**`site/` 被删空，并把残版推上了线**（4 个前端文件 404）。
→ 重建前要停**所有**占用者（`8787` 的 wrangler dev **和** `8899` 的 http.server）；
部署后**别立刻验证**（CDN 有传播延迟，会误判成失败）。
