## 五、本次修的四个真 bug / 能力缺口（均有回归测试）

1. **`jobs` 把在跑的任务误判成 `failed`**（会诱导人重开任务 → 截断产物、毁断点）。
   根因：`pid_alive()` 用 `tasklist` + 管道捕获，受限环境下失败即返回 False。
   修复：改用 `kernel32.OpenProcess/GetExitCodeProcess`；加「日志 mtime 新鲜」兜底；误判自动纠正回 `running`；
   `kill_job` 改 kernel32 杀**整棵进程树**（本机 `taskkill` 实测 `Access denied`），并加 pid 复用保护。
2. **ASR 因音频尾部坏包把整段转写判 failed**。`圣剑英雄谭.mp3` 最后 0.7 分钟解码报
   `InvalidDataError`，已解码进内存的十几分钟被丢弃。修复：坏包停手 + 保留成果 + warn 日志；
   但「一点都没解出来」仍按失败抛出，不允许静默产出空稿。
3. **`store` 的「净变更」判据只看条目数量 → 纯更新永远回填不进去**（2026-10-03 二轮答疑时暴露）。
   旧代码：`if plan.counts_after == plan.counts_before: 跳过回填` ——
   而「更新角色 N（追加 note / events / 称呼归一）」**不改变条目数**，于是计划里明明写着「更新角色 1」，
   回填却被跳过。修复：改为判断 `new_characters / updated_characters / new_relations / new_players /
   updated_profiles / normalized` 是否有任意一项非空。
   → 本次「结刻＝杰克」的 cross_jieke 更新就是靠这个修复才写进生产库的。
   回归用例：`test_slice1` 新增「[4b] 纯更新回填」两项检查。
4. **`character_updates` 不支持改名**（Q18 落地时暴露）：补丁里改 `characters[].name` 对**已存在**的 id 无效
   （store 会把它当「重复」跳过），于是 ASR 错字改名只能手改数据。
   修复：`merger` 新增 `set_name` 字段（走既有的 `target.update(changes)`），回归加「set_name 改名生效」检查。
   → 本次「艳术长老 → **鼹鼠人长老**」就是靠它落地的。

**回归**：`test_slice1` **35/35** · `test_e2e` **20/20** · `test_jobs`（新）**25/25** · 关系图 HTML 结构校验通过。
