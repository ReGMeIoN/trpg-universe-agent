## 一、参考图拆解：其实是**三层信息架构**

| 图 | 层级 | 关键设计元素 |
|---|---|---|
| `219281da…` | **L0 势力总览** | 势力 = **六边形**（半透明彩色填充 + 同色描边 + 内置褪色徽记）；名牌 = 中/英文名 + 人数徽章 + `UPDATED` 标签；势力间细蓝光线；底是冷灰蓝 + 虚线网格 |
| `495c6733…` | **L1 关系网** | 角色 = **卡片**（立绘 + 底部深色名牌 + 左上角编号 + 顶部状态条 `NEW/UPDATED`）；势力 = **包住自己成员的彩色多边形外框**（凸包），框内还有小组名牌（「行动组A4」+ 图标）；连线 = **宽柔光 + 细亮芯**的金/白光线；背景有大幅水印字 |
| `b84b360c…` | **L1 悬停态** | 悬停卡片**放大 + 白色发光描边**；名字下方浮出「人物详情」按钮；其它元素整体变暗；聚焦的连线变**金色** |
| `6186e316…` | **L2 人物档案** | 左侧**大幅立绘**占满；左下角职业图标 + 英文名 + **大号中文名**；右侧半透明档案面板（【代号】【性别】【出身地】【种族】【身高】…+ 大段正文）；灰底细线分隔 |

**提炼出的视觉规则**（这些才是要抄的东西）：
1. **节点是有厚度的卡，不是圆头像**——立绘 + 名牌 + 编号 + 状态条。
2. **势力是有颜色的"容器"**——用半透明彩色多边形把成员圈起来，容器带自己的名牌与大徽记。
3. **连线是"光"**——不是一根线，而是「宽而柔的外晕 + 细而亮的内芯」两层叠出来的假 bloom。
4. **聚焦态 = 放大 + 发光 + 其它变暗**，金色是"当前关注"的语义色。
5. **背景永远不是纯色**——冷灰蓝 + 网格/蓝图纹理 + 大幅水印字，制造"仪表盘"感。
6. **字排**：中文名用粗衬线、英文名用细窄无衬线、标签用全大写小字 + 宽字距。

## 二、我们的数据对照（能对上什么、缺什么）

### ✅ 能直接对上
| 参考图概念 | 我们的字段 |
|---|---|
| 势力 | `groups[]`（14 个团） |
| 卡片立绘 | `avatar`（竖图 832×1216 或卡内原图） |
| 卡片编号 | `id`（如 `yy_yuxiuli` / `mg6_gordon`） |
| 状态条 | `tags[]`（PC / NPC / BOSS / 跨团 / 待确认） |
| 连线颜色 | `strength`（强/中/弱） |
| 连线类型标 | `type`（**已归并成 24 个标准类型**） |
| 档案正文 | `identity` / `note` / `events[]` |
| 关联列表 | `relations[]` 的 `event`（带出处） |

### ⚠️ 缺的 / 要造的
| 缺什么 | 怎么办 |
|---|---|
| 势力徽记 | **我们自己造**：每个团一个几何符号（SVG），按团名走确定性生成 |
| 稀有度（6★/5★） | 换成**角色类型色条**：PC 金 / NPC 灰 / BOSS 红 / 跨团 紫 / KP 蓝 |
| 大幅 splash art | NPC 只有竖立绘（832×1216，2:3）——**恰好适合卡片**；档案页竖着摆也够 |

### ❌ 最大的两个硬约束（必须让主人知道）

**约束 1：立绘缺口 106 / 237 人。** 只有 3 个团"照片齐全"：

→ L0 总览层的团间连线**不能用关系边**，要用**「共有角色」**（谁同时在两个团里出场）才画得出来。

## 三、我的方案

### 3.1 四层钻取（照参考图的信息架构）

```
L0 势力总览   团 = 六边形盾徽（人数 + 立绘马赛克 + PL 徽章）
             团间连线 = 共有角色（杰克→5 个团各一条，线的粗细 = 共有几人）
   ↓ 点一个团
L1 团内关系网  角色卡 + 势力外框 + 光线；**团内再自动分小队**（做「行动组A4」那种内层小组框）
   ↓ 点一个人
L2 焦点模式    相机推近、其余变暗；只留「关系最密切的 N 人」（按 强度×条数 排行）
             连线加"光在流动"的动画（stroke-dashoffset）
   ↓ 再点一次
L3 人物档案    左：立绘大图（可放大/切换形态）  右：档案面板
             代号 / 身份 / 扮演者 / 出场团 / 标签 / 关系数 / 简介 / **事件年表** / **关系清单**
```

### 3.2 四种「分组视角」切换（同一引擎，换 hull 与配色）

这是我最想加的一层——**参考图的"势力"概念，我们不只有一种切法**：

| 视角 | 分组依据 | 回答什么问题 | 数据现成度 |
|---|---|---|---|
| **按团**（默认） | `groups[]` | 这个团里有谁 | ✅ |
| **按创作者** ⭐ | `played_by` | **谁写的角色卡 / 谁演的** | ✅ 191/237 有扮演者 |
| **按角色类型** | `tags[]` | PC / NPC / BOSS / 跨团各是谁 | ✅ |
| **按自动社群** | 社群发现（Louvain） | **数据自己会分成哪几撮**（可能跨团） | 需装 networkx |

「创作者」视角的实测弹药：
```
pd 69（KP 代演的全部 NPC）· 菌羊 32 · ReGMeoN 12 · 雪人 12 · 宽 11 · 往 9
· 叶珏 2 · 牛爷 2 · 阿翔 2 · 俊松 2 · DeIta 1 · 卡尼三三 1
```
→ 一屏就能看出「**pd 一个人扛了 69 个 NPC**」这种结构，很有信息量。
另外还有第三条"创作者"线索：**角色卡来源**（卡内导入 / NAI 生成 / 玩梗 / 跨团同位体），可以做成卡片上的小角标。

### 3.3 美术风格：不照抄，做我们自己的

**概念：「跑团档案库 · 观测终端」**——冷色全息 UI + 档案封条质感。

- **底**：深冷灰蓝渐变 + 蓝图网格 + 极淡扫描线 + 细噪声（全 CSS/SVG，零素材）
- **每组一套主题色 + 纹样**（这是"独特风格"的关键，让 14 个团各有个性）：
  圣剑英雄谭＝羊皮纸金 / 阴阳差事录＝朱砂墨 / 魔法少女系列＝薄荷粉 / 伪人群＝故障红 / 无敌巨鲨＝深海蓝 …
- **卡片**：立绘裁 3:4 + 底部名牌（中文粗衬线）+ 左上编号牌 + 顶部类型色条 + 四角细切角
- **连线**：双层描边假 bloom；强=金、中=橙、弱=灰；**类型用线型区分**（实线=合作、虚线=敌对、点线=情报…）
- **档案页**：右侧面板加**朱砂印章**「已入库 / 待确认」，呼应跑团记录的手稿感
- **无立绘的角色**：**剪影卡 + 「未解封」封印**（比空白卡片体面，而且自成设定）

### 3.4 技术方案（零依赖、离线可开）

| 项 | 选择 | 理由 |
|---|---|---|
| 渲染 | 纯 vanilla JS + SVG + CSS | 沿用 `net_html.py` 的路子；不引 CDN，双击即开 |
| 布局 | **确定性分区布局**（不是 force-directed） | 237 节点用力导向会抖、每次不一样；确定性布局可复现、好截图 |
| 相机 | 一层 `transform: translate/scale` + CSS transition | 缩放/平移/推近都靠它，点击聚焦 = 改 transform |
| bloom | 同一条线画两遍（宽半透明 + 细亮芯） | 比 SVG filter 便宜得多，视觉几乎一样 |
| 性能 | 缩略图 + `IntersectionObserver` 懒加载 | 237 张立绘不能一次性解码 |
| 动画 | 入场交错 fade+scale、连线 dash 流动、悬停放大发光 | 全 CSS，不写动画库 |

## 四、需要主人拍板的 4 件事

1. **立绘缺口怎么办？**
   - (a) 先补第二批 105 人（19 团的老角色，NAI 约 1 小时）→ 全库都能上游戏风
   - (b) 先用「未解封剪影卡」上线，只做 3 个照片齐全的团
   - (c) 混：主推 3 团做样板，其余团"未解封"占位
   👉 我推荐 **(c)**：立刻能看到成品，也不挡后续补图。

2. **要不要团内自动分小队？**
   参考图里「行动组A4」那种内层小组框很好看，但自动社群（Louvain）可能与你的剧情认知不符。
   → (a) 先跑出来给你审 (b) 先不做内层框，等你有空手定小队名单。

3. **范围**：先做 **1 个团当样板**（我建议圣剑英雄谭，26 人全有立绘、关系最密）
   还是三个团一起（阴阳/圣剑/mg6）？

4. **风格取向**：(a) 冷全息仪表盘 (b) 纸档案/手稿 (c) **每组一套主题色**（我推荐）

## 五、我的建议顺序

```
① 用圣剑英雄谭做一个「四层钻取」样板（26 人全立绘，最省事、效果最足）
② 你看着调美术（配色/卡片比例/动画节奏）
③ 定稿后做成「按团 / 按创作者 / 按类型」三视角切换
④ 再把其余团并进来（照片不全的先用「未解封剪影卡」）
⑤ 最后考虑上站（Cloudflare）+ 手机端适配
```

技术上都做得到，**唯一的真实风险是"照片不全"和"团间没有边"这两条数据约束**，
其余都是设计活。样板大概 1～2 轮就能看到能点能钻的第一版。
