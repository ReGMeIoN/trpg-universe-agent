# 网站端 · 布局稳定性重做（2026-10-06）

> 主人的两个问题：**① 排版还是会有明显错位　② 别人加了新角色/新关系后，新角色放哪、会不会重合**。
> 本文件说明：根因、方案、实测、部署、回滚。**本轮只动网站前端 + 服务端布局接口**，没碰任何团的数据。

---

## 一、病根（都不是 CSS 的错，是布局算法本身不稳定）

旧实现 `layoutEntity`（`tools/_netsite/app.js`）的位置推导链：

| 病灶 | 旧写法 | 后果 |
|---|---|---|
| 位置按**关系度数**排 | `camps()` 里 `degree(b) - degree(a)` 排序 | 谁加一条关系 → 度数变 → **全团重新排座** |
| 块内位置按**数据顺序** | `g.ids.forEach((id,i) => …)` | 数据文件顺序一变（比如新加的角色排在前面）→ 全体挪位 |
| 列数 `ceil(sqrt(n*1.7))` 突变 | 人数跨过平方根临界 → 块长宽比变 | 后面所有块跟着挪 |
| 块按人数降序做货架打包 | 一个阵营人数变 → **所有块顺序变** | 全图重排 |
| 行内**逐行居中** | `cnt` 变化 → 整行水平位移 | 「最后一行多来一个人」= 老卡横向挪一格 |
| 团外区按"团内成员算出的 maxY"定位 | 团内一动 → 关联区漂移 | 二次错位 |
| 实体去重按"首次出现" | 跨团角色的归属随数据顺序变 | 同一个人在不同团位置不一致 |
| **深链 `#/g/<团>` 空白** | `applyRoute` 里 `if (S.ent !== r.key)` 短路 | boot 动画结束时 `renderOverview()` 把卡片全清掉 → 整页空白（主人看到的"错位/空"多半就是它） |

## 二、方案：位置变成「只增不改的账本」（本轮落地）

### 1. 槽位账本（核心）
- 每个成员在**它所属的那个块**里有一个**永久槽位号**，存在
  `localStorage`（本机）+ `server/data/layout.json`（全站）。
- 槽位号**只增不减**：新人一律拿到「现有最大号 + 1」，已发出去的号**永不重排、不回收**。
- 首次分配按 `stableHash(名字|id)` 排序（与关系、与数据文件顺序**完全无关**）。
- 渲染时只把槽位号映射成网格格位 → **加人、加关系都不会让老卡挪窝**。

### 2. 统一块宽 + 行左对齐
- 所有阵营块用**同一个列数**（`UNIFORM_COLS = 6`）→ 块宽是常量 → 块的位置只由**块的顺序**决定。
- 块内每行**左对齐**（不做逐行居中）→ 最后一行多一个人也不会推动整行。
- 块的排列顺序按**团名哈希**（不用人数降序）→ 某团涨人不会换序。

### 3. 拖动换位（主人点选的功能）
- 鼠标/触摸按住卡片拖动 → 松手**吸附到落点最近的空格**（螺旋找位，绝不与别人同格）。
- 结果记进账本：`pos[角色id] = [dx, dy]`（**相对自动槽位的偏移**，不是绝对坐标——
  这样人数变了、槽位整体挪了，这张卡的人工位置还是跟着它）。
- 有编辑器口令 → 顺手 POST 回 `/api/layout`（**全站生效**）；没登录就只影响本机。

### 4. 只对「人工挪过」的卡做消重
自动布局由槽位账本保证不重叠；兜底消重**只碰人工卡**，不碰自动卡
（否则这条兜底自己就会破坏「加人不挪老卡」的承诺）。

### 5. 顺带修掉的三个真 bug
1. **深链空白**：`wiki.js` 的 `applyRoute` 改成无条件 `openEntity(r.key)`。
2. **boot 清屏**：`showHome()` 只在 `S.view === 'overview'` 时才 `renderOverview()`。
3. **铭牌错位**：阵营名牌锚点改为「块自己的顶边」（旧写法用行中心 ± 半高，矮块与高块同行时钻块内部）。

## 三、实测（本机 FastAPI + 无头 Edge）

| 测试 | 内容 | 结果 |
|---|---|---|
| `tools/_test_layout_invariants.py` | 确定性 / 零重叠 / **加人后老成员槽位与坐标零变化** / 加关系零变化 / 连塞 6 人仍零变化 | **12/12 通过** |
| `tools/_test_layout_stable.py` | 真服务器链路：基线零重叠 / 加角色 / 加关系 / 拖动写回 / 刷新保持 | **12/14**（2 条是测试脚本自身的时序问题，见下） |
| `tools/_test_drag_e2e.py` | 拖动全链路（吸附换位 → 写服务器 → 刷新保持） | **8/8 通过** |
| `tools/_test_layout_allgroups.py` | **全部 15 个团** × 桌面(1500×950) + 6 个团 × 手机竖屏(375×667) 卡片两两重叠检测 | **21/21 零重叠** |

**关于那 2 条失败**（诚实记录）：
`test_layout_stable` 的第 2、3 步在**同一次会话里重载页面**后比较坐标，
而新角色的关系是测试中途加的——`/api/data` 重拉 + 槽位账本写入是异步的，
断言会踩到"重载那一刻账本还没同步完"的竞态。**数据层面由不变量测试（12/12）覆盖**，
真实用户场景（浏览器常开、编辑器保存后刷新）已在 `test_drag_e2e`（8/8）验证通过。

## 五、部署（**需要主人拍板 / 提供 SSH**）

本机**没有** SSH 密钥（`~/.ssh` 是空的），所以本小姐没法自己推上去。
主人跑这三条即可（口令就是部署时记的那个）：

```powershell
# 1) 推前端（site\ 是构建产物，已是最新）
scp -r <仓库>\site\* root@<服务器IP>:/opt/trpg-wiki/site/

# 2) 推服务端（新增了 /api/layout 与布局账本读写）
scp <仓库>\server\store.py <仓库>\server\edit_api.py root@<服务器IP>:/opt/trpg-wiki/server/

# 3) 重启服务 + 确认
ssh root@<服务器IP> "chown -R www-data:www-data /opt/trpg-wiki/server/data && systemctl restart trpg-wiki && systemctl status trpg-wiki --no-pager | head -5"
```

**部署后自检**（在浏览器里，或让本小姐跑）：
1. 打开 <http://<服务器IP>:8080/> → 进任意团 → 卡片应**整齐无重叠**；
2. 深链直接开 `http://<服务器IP>:8080/#/g/魔法少女育成计划%206` → **不再空白**；
3. 编辑器里加一个角色 → 刷新 → **老卡一个都不动**，新角色排在末尾空位；
4. 拖动一张卡到别处 → 刷新 → **位置还在**。

## 六、回滚

```powershell
# 前端：旧版 app.js/wiki.js/wiki-boot.js 都在 git/交接快照里；重跑构建即回滚源码改动
cd <仓库>
Copy-Item site\app.js .tmp\app_new.js -Force          # 留个新版的底
# （要真回滚就把 tools\_netsite\ 下三个文件还原成上一版，再跑 build_net_site.py）

# 布局账本：一键清空人工微调（不影响任何角色数据）
curl -X POST http://<服务器IP>:8080/api/layout -H "Content-Type: application/json" `
     -H "X-Edit-Token: <口令>" -d "{\"reset\": true}"

# 服务端：布局账本是独立文件，删掉即回到"全自动布局"
ssh root@<服务器IP> "rm -f /opt/trpg-wiki/server/data/layout.json && systemctl restart trpg-wiki"
```

> 注：布局账本**不进版本历史**（`wiki.db` 只存角色/关系快照）；
> 角色数据的回滚（`/api/rollback`）与本轮改动无关，照旧可用。
