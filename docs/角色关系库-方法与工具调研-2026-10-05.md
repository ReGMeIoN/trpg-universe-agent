# 角色关系库 · 方法与工具调研（2026-10-05）

> 起因：主人问「有没有适合做这方面数据库的方法或者工具，搜一搜案例」。
> 下面按 **能不能直接用 / 要不要抄方法 / 不用碰** 三档分类，最后给本项目的落地建议。
>
> 本项目的规模先摆在这，选型全靠它：
> **237 角色 / 442 关系 / 14 团 / 12 位 PL**；`events[]` 里**带段号与秒级时间戳**；
> 已经有：团群像关系图（`<团>_关系图.html`）、单人 ego 网（`角色网_<名>.html`）、
> 度数排名、立绘链路、KB 包导出。
> **规模小（几百节点）→ 图数据库/集群那套基本是过度设计。**
>
> 顺手量了两个决定优先级的事实（工具 `tools\_relation_stats.py --types`）：
> - **442 条边有 387 个不同的 `type` 串**，最多的「对手」也只 15 次；239 个串是「A/B」复合写法。
>   → **关系类型现在是自由文本，任何按类型的统计都是失真的**（这是第一优先级的问题）
> - **222/442（50%）的 `event` 里已经带「段N」或 `[秒]` 时间锚** → 时间轴分析是现成燃料
> - 强度分布：强 148 / 中 246 / 弱 48

## 二、数据模型 / 本体：抄思路，别抄重量

### 2.1 GOLEM：为「小说 + 读者反应」建的本体与知识图谱
- [The GOLEM: an ontology and knowledge graph for fiction and reader response](https://zenodo.org/records/8206554)
- [Constructing the GOLEM: Graphs and Ontologies for Literary Evolution Models](https://zenodo.org/records/8107749/files/PIANZOLA_Federico_Constructing_the_GOLEM__Graphs_and_Ontolog.pdf?download=1)
- [Metadata and Derived Data in Computational Literary Studies: The GOLEM Case](https://zenodo.org/records/15127892/files/YANG%20Xiaoyan-PIANZOLA%20Federico_Metadata%20and%20Derived%20Data%20in%20Computational%20Literary%20Studies.%20The%20GOLEM%20Case.pdf?download=1)

**可抄的三点**：
1. **节点分两类**：作品内实体（character/place/event）vs 作品外元数据（reader response、版本、来源）。我们的对应物是「角色/团/PL/素材」，现在混在 `tags` 里。
2. **关系要能溯源**（provenance）：每条边标「从哪段文本推出来的」。我们已有 `event` 字段，但**没结构化成出处**（现在是一句话）。
3. **"derived data" 与 "source data" 分表**：他们专门讨论「派生数据要能重算」。我们 `relations.json` 就是派生数据，但和 `characters.json` 混在一层。

### 2.2 属性图 + 时间有效性（工业界的标准做法）
- [Temporal data model grounded in the standard Property Graph definition（ACM）](https://dlnext.acm.org/doi/pdf/10.1145/3828820?download=true)

**要点**：边带 `valid_from / valid_to`（双时态则再带 `recorded_at`），查询时按时间点切片。
**我们的机会**：`events[]` 里已经有「段N」「[4061.98-4062.98]」这种时间锚，
**完全可以给关系边补 `from_ts` / `to_ts`，做成"关系随时间生长"的动画或切片**——
这就是 `references/数据与文本.md` §五 说的「关系数据自带时间轴」，只是还没兑现。

### 2.3 DraCor：戏剧语料的"可编程"做法
- [Exploring Programmable Corpora（CLSINFRA 论文）](https://zenodo.org/records/15111965/files/Trilcke_Exploring_Programmable_Corpora_Case-Study%20.pdf?download=1)
- [DraCor MCP 评估仓库](https://github.com/dracor-org/dracor-mcp-evaluation/blob/da9d4230bdb36584469bb26eec40469e2694a27e/2025_cda-preprint_documentation/5-1_DraCor-MCP-Paper_2025-07.md)

**要点**：把每部剧做成标准 TEI 标注 + 统一 API（`/characters`、`/relations`、`/network`），
让**外部工具**能直接拉数据算。他们甚至做了 **MCP server**，让 LLM 直接查语料。
→ 我们的对应物是 `relations.json` + `characters.json`：
**只要给个稳定的小 API/CLI，就能接任何分析工具**（现在靠 `tools\_*.py`，够用但不成体系）。

## 三、分析方法：这一块最值得抄（有整支文献）

### 3.1 人物网络 + 社群发现 + 中心性（最经典的组合）
- [Unsupervised cluster analyses of character networks in fiction: Community structure and centrality](https://www.sciencedirect.com/science/article/abs/pii/S095070511830491X)
- [CapekDraCor: A New Contribution to the European Programmable Drama Corpora](https://www.sav.sk/?lang=en&doc=journal-list&part=article_response_page&journal_article_no=31223)
- [Social Network Analysis: A New Lens for Digital Humanities and Social Science](https://ieeexplore.ieee.org/document/11390907)

**常算的指标**（都能直接套到我们的 442 条边上）：
| 指标 | 回答什么问题 | 对我们的价值 |
|---|---|---|
| **度 / 加权度** | 谁是红人 | 已有（`--rank`） |
| **介数中心性 betweenness** | 谁是不可绕过的**桥** | ⭐ 高——找出「团长级枢纽」和「跨团中介」 |
| **接近中心性 closeness** | 谁能最快接触到全团 | 中 |
| **特征向量 / PageRank** | 谁被"重要的人"围着 | 中 |
| **聚类系数 / 社群（Louvain、Leiden）** | 不看团名，**数据自己会分成哪几撮** | ⭐ 高——能验证"团"是不是天然社群，也能挖出跨团小团体 |
| **割点 / 桥边（articulation point）** | 去掉谁网络就断 | 高——剧情上"关键人物"的量化定义 |
| **同配性 assortativity** | 强关系是不是扎堆 | 低 |

> 有个现成的教学案例：**《哈利·波特》的 betweenness 分析**发现德思礼一家其实是"桥"。
> 见 [Zenodo 上的 Harry 分析 PDF](https://zenodo.org/records/15793163/files/HARRY5.pdf?download=1)。

### 3.2 动态 / 时序人物网络（我们最该补的一块）
- [GraphLit: Learning Text-Enriched Dynamic Character Network Representations for Literary Study](https://export.arxiv.org/pdf/2605.28643)
- [Relational arcs as narrative structure: dynamics, distribution, and diachronic change in fiction（Cambridge）](https://www.cambridge.org/core/services/aop-cambridge-core/content/view/37947D31A93A7FA276BC3E6BA67C5DFD/S2977815825100213a.pdf/relational_arcs_as_narrative_structure_dynamics_distribution_and_diachronic_change_in_fiction.pdf)
- [Temporal Embeddings and Transformer Models for Narrative Text Understanding](https://ar5iv.labs.arxiv.org/html/2003.08811)

**"relational arc"（关系弧）**这个概念特别好用：把某条关系按时间画成曲线（亲密度/强度随剧情变化），
就能看出「从敌对到同盟」「从师徒到决裂」。
→ 我们有段号 + 秒级时间戳，**这一块是现成燃料，只是没做**。

### 3.3 现成的社会网络分析方法清单
- [AlterLab SNA methods 参考](https://github.com/AlterLab-IEU/AlterLab-Academic-Skills/blob/f849bcb140136cff582c12292bc35b5511d053b3/skills/social-science-workflow/alterlab-sna/references/sna_methods.md)

一个不错的"指标 + 该配什么图"速查表，可以直接照着给本项目列分析菜单。

### 3.4 计算机文学研究的经典样板
- [Six Degrees of Francis Bacon（CMU）](https://www.cmu.edu/news/stories/archives/2013/june/june12_francisbacon.html)
  —— 早期现代人物网络，**证据链 + 置信度**的做法值得学（我们有 `confirmed` 字段，方向一致）
- [Network of Thrones（AMS Math Moments #123）](https://www.ams.org//publicoutreach/mathmoments/mm123-thrones-podcast)
  —— 把《冰与火之歌》第三卷做成人物网络，是"叙事网络"最出圈的案例
- [Tolkien 叙事结构的计算建模](https://www.zenodo.org/records/19370250/files/computational-modeling-and-analysis-of-narrative-structures-in-tolkien-TRADE-PRINT-READY%20mp.pdf?download=1)
  —— NER 抽角色再建网，和我们的路子一模一样

## 六、本项目的落地建议（按性价比排序）

### ⭐⭐⭐ 立刻能做、零新依赖
1. **关系类型受控词表**（**本小姐实测：442 条边有 387 个不同的 `type` 串**，
   出现最多的「对手」也只有 15 次；其中 239 个串还带「/」复合写法，覆盖 262 条边）。
   → 现在任何按类型的分组统计都是失真的。**归并成 15~25 个标准类型 + 保留原串**（原串进 `type_raw`）。
   **参考 Obsidian Relations 的"类型化连线"**：类型定了，连线样式/颜色/过滤才有意义。
2. **关系边补时间锚**（**实测 222/442 = 50% 的 `event` 里已经有「段N」或 `[秒]`**），
   抽成 `from_ts` → 产出 `relations_timeline.json`；没锚的那一半按段近似。
3. **`_ego_net.py` 加"只看强关系"开关**，做骨架图（现在 强148 / 中246 / 弱48）。

### ⭐⭐⭐ 需要 `pip install networkx`（纯 Python + numpy，本机已有 numpy）
4. **中心性报告**：介数/接近/PageRank 一页出全 → `产出\关系统计_中心性.md`
5. **社群发现**：Louvain 把 14 个团和跨团小团体一起跑，看**数据自己的分群**和人工团的差异
6. **割点/桥边**：找出"去掉他网络就散"的角色 —— 剧情关键人物排行

### ⭐⭐ 中等工作量
7. **关系弧 / 动态网络**：按段切片，出「关系演化动画」或「某条关系的强度曲线」
8. **团际连线图**：14 个团当节点、跨团角色当边，画"跑团宇宙"的骨架（现在完全没做）
9. **PL ↔ 角色二部图**：每个 PL 演过哪些角色、同台过谁

### ⭐ 大件（先不做）
10. **关系库 MCP server**：把查询包成 MCP 工具，DSH 里直接问"谁跟杰克关系最强"
11. **自然语言问答**（GraphRAG 简化版）
12. **图数据库**：442 条边 / 237 节点 —— **明确不需要**

## 七、一句话结论

学术界的「人物网络」方法（中心性 + 社群发现 + 动态演化）**可以直接搬**，
工具链用 **NetworkX** 就够（本机只差一个 pip 包）；
Neo4j / Gephi / Cytoscape 这类在我们的规模下是**过度设计**；
World Anvil / Obsidian Relations / grimoire-mcp 值得抄的是**关系类型受控词表**和**把库包成工具给 AI 用**这两个思路。
