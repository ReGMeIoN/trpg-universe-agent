## 一、十五步链路（九步主链 + 本轮补出来的六步）

| # | 步骤 | 命令 | 产物 | 验收判据 |
|---|---|---|---|---|
| 1 | **ingest** 登记素材 | `python -m trpg_agent ingest` | `.trpg/manifest.json` | 新团文件按目录名归团；`group_source=dir:<团名>` |
| 2 | **transcribe** 转写 | `python -m trpg_agent transcribe --group "<团名>"` | `素材\<团名>_转写.txt` | 段数与音频时长匹配；质量自检保留率 ≥97% |
| 3 | **segment** 分段 | `python -m trpg_agent segment --group "<团名>"` | `.trpg\segments\<团>_段N_*.txt` + 索引 | 段数 = ⌈总时长/3770s⌉；未解析行 0 |
| 4 | **extract** 提炼 | `python tools\extract_all.py --only "<团名>"`（先 `--dry-run`） | `.trpg\patches\<团>_patch.json` | 角色/关系/待确认三项数量合理；canon 注入字数 >0 |
| 5 | **review·答疑核对** | `tools\_quiz_check.py` → `tools\_clip_quiz.py --tag 第N轮` | `产出\<团>_疑问核对*.html` + `产出\quiz\<团>_第N轮\*.mp3` | **剪片段前关键词命中 0 遗漏** |
| 6 | **chronicle** 编年史 | `python tools\_chronicle.py --group "<团名>"` | `产出\<团>_剧情编年史.md` | 逐段小节 + 时间戳；存疑处带 `?` |
| 7 | **store** 入库 | 影子库预演 → `store --apply --allow-production --group "<团名>"` | `数据\*.json` + `数据\*.bak_store_*` | 入库前校验无问题；写后复验通过 |
| 8 | **visualize** | `python -m trpg_agent visualize --group "<团名>"` | `产出\<团>_关系图.html` / `_关系网.md` / `PL画像可视化.html` | `tools\check_html.py <产出目录>` 全通过 |
| 9 | **housekeep** 收尾 | `python -m trpg_agent housekeep` | `产出\收尾清单.md` + 备份轮转 | 清单里的数据量 = 当前库 |
| 10 | **答疑落地**（写回补丁） | `tools\_fix_patch_yy.py` / `_fix_patch_mg6.py --apply` | 更新后的补丁 + `.bak_ownerqa_*` | `_pending_report.py` 的 pending 归零 |
| 11 | **PL 画像** | `tools\_pl_profile_from_drafts.py --distill --apply` | `pl_profiles` 的 speaking/rp/impressions | 每个 PL 有本团角色 + 至少一条印象 |
| 12 | **立绘登记** | `tools\_apply_portraits_new.py --apply` | `数据\头像\<团>_<角色>.<ext>` + `avatar` 字段 | 复验 N/N；关系图里能引用到 |
| 13 | **人工文档合并** | `tools\_sync_manual_docs.py --apply` | `产出\杰克档案.md`（手写）· `跑团宇宙总览.md`（自动）· KB 包副本 | 自动版就地维护、手写版只增不删 |
| 14 | **数据卫生** | `tools\_clean_dirty_groups.py --apply` | `groups` 只留团名 | 脏值 0；团数 = 关系图团数 |
| 15 | **export** KB 包 | `python -m trpg_agent export` | `产出\astrbot知识库导入\*.md` | 每团一份 + 00_/00b_/00c_ 索引文件 |

## 二、配置口径（本项目实测最优）

```yaml
asr:
  model_path: "<工作区>/素材/_whisper_models/large-v3"   # 2948 MB
  device: cuda            # RTX 4060 Laptop 8G，显存占用约 6.1 GB
  compute_type: float16
  beam_size: 5
  batched: false          # 批式推理已否决（见坑 §五.2）
  condition_on_previous_text: false   # 又准又快：保留率 98.7%、复读 2 段、速度 ×1.78
  window_s: 1800
  initial_prompt: <团专属词表，按次用 --prompt 传>
llm:
  extract: deepseek-flash（json_object，max_tokens 32000；推理型模型，给小了会空 content）
```

**团专属口径三件套**（都别塞进全局配置）：
- ASR 词表：`.trpg\prompts\asr_<团名>.txt` → `transcribe --prompt (Get-Content -Raw ...)`
- 提炼规则：`.trpg\canon\groups\<团名>.md`（只在本团提炼时注入）
- 编年史口径：`.trpg\prompts\chronicle_<团名>.md`

## 四、数据契约与安全闸门（不许破坏）

- **写前必备份**：`数据\*.bak_store_<时间戳>`；定向改数据也要 `.bak_<用途>_<时间戳>`
- **`confirmed:false` 一律不写盘**（降级进 pending）→ 所以「放行」必须显式改 confirmed + 摘掉 `待确认` 标签
- **store 只支持新增/追加**：改关系端点、改 note 措辞、撤 groups 都要**直接改数据**（store 会把旧值当新增再加一遍）
- **`append_note` 已改幂等**（2026-10-05）：判「原文是否已出现」，重复 `--apply` 不再越写越多
- **补丁是唯一入口**：库里的改动都要在补丁里同步（否则下次 `--apply` 会打回来）
- **影子库预演**：`tools\_shadow_sync.py --apply` → `store --apply --ws <shadow>`（root≠production_root，闸门自动放行）
- **`groups` 只放团名**；跨团性用 `tags`（`data_utils.is_real_group` 守卫 + `_clean_dirty_groups.py` 清理）

## 五、踩坑全集（都花过时间，别再踩）

### ASR / 环境
1. **Windows 上没有 CUDA 运行库**：`ctranslate2` 按名字 `LoadLibrary("cublas64_12.dll")` → 必须装
   `nvidia-cublas-cu12` / `nvidia-cudnn-cu12`（+ `nvidia-cuda-nvrtc-cu12`），并在适配层把
   `site-packages/nvidia/*/bin` 加进 DLL 搜索路径（已封装 `_prepare_cuda_dll_search()`，`ASR_CUDA_DLL_DIRS` 可救急）
2. **`BatchedInferencePipeline` 不可用**：`clip_timestamps` 每个 clip **只解码前 30 秒** → 长语音块静默丢内容；
   实测还更慢 + 幻觉。`beam_size=1` 也别为了快就用（断句碎、错字多）
3. **`--prompt` 按次传词表**：`initial_prompt` 进断点指纹，改 `config.yaml` 会把上一个团的断点判废
4. **断点续跑是常态**：同团同配置重跑即续；日志要出现「检测到断点…」+「已截断产物到断点偏移…」
5. **一个团多份录音必须分片命名**：否则后一份覆盖前一份（已修：`part_tag`，产物+断点双隔离）

### 数据 / 流程
6. **团专属内容别塞全局 `canon_rules.md`**：它注入每一个团 → 用 `canon/groups/<团名>.md`
7. **`canon build` 要跟上入库**：本会话差点漏——名单还停在 162，会导致下个团重复建节点（刷新后 237）
8. **悬空端点**：关系两端必须都入库；`confirmed:false` 的节点不算存在 → 用 `_review_patch.py --dangling` 先查
9. **store 的 `append_note` 原来不幂等**：同一句会被写 2~3 遍（已修 + 影子库实测）
10. **答疑匹配别用 `reason`**：只匹配 `item` 文本；否则 reason 里出现「KP」就把不相干条目也判成已答（本会话两处误配）
11. **「一问两半」条目**：要留 residual pending，别整条归档（如「名字已答、机制未答」）

### 工具 / 编码
12. **CJK 路径别写进 pwsh 内联 Python**（PS 5.1 按 GBK 解析 → 路径变乱码，`is_file()` 静默 False，
    看起来像"文件不见了"）→ 一律写 `tools\*.py`，或路径变量从 `Get-ChildItem` 取
13. **内联 Python 里的 `|` 会被 PowerShell 当管道**（`InvalidEndOfLine`）→ 同上，写文件
14. **切图/挑图先看图再登记**：卡内图里混着**团名书法匾额**和**徒弟卡面截图**（本会话 6 张卡都中过），
    「取最大图」必错；`_立绘.jpg` 这类显式命名的才可直接用
15. **`check_avatars.py` 报的 `.jpg` vs `.png` 不一致**可能只是旧团历史遗留，建站时才影响
