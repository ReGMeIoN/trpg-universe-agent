### L1 的「阵营」分类（2026-10-05 返工）

第一版 L1 的子分组是「按度数取种子 + 收邻居」，再把**种子的人名**当组名 → 出现「神川玛利亚组」
这种看着像"某人的小队"的标签。**已改成按库里的真实字段分类**：

| 阵营 | 依据 |
|---|---|
| 玩家角色 | `tags` 含 `PC` |
| BOSS | `tags` 含 `BOSS` |
| 跨团 | `tags` 含 `跨团` |
| KP | `tags` 含 `KP` |
| NPC | 其余 |

外壳用阵营名 + 人数（横向铭牌，挂在每块左上角），**不再出现人名**。
排布用**货架式打包**（按块面积算目标行宽，小的阵营并到一行），避免大阵营独占一行、小的堆成竖条。

> ⚠️ **铭牌的锚点必须用「该块卡片的真实位置」算**，不能用「块自身高度 h/2」：
> 同一行里矮块与高行**共用行中心 cy**，用 h/2 会让矮块的标签钻到块内部去——
> 这就是主人看到的「玩家角色 tag 明显错位」（2026-10-05 修）。

> 试过用 identity 关键词猜阵营（考核官/学生/魔女…），结果把「玩具熊／小丑」判成考核官、
> 把「马卡龙」判成异兽 —— **不可靠，弃用**。要按剧情阵营（三魔女/学院/十二工作…）分，
> 得主人给一份名单，本小姐照做。

**右上角三种分组视角**（同一个引擎，换外壳与配色）：

| 视角 | 分组依据 | 一眼能看出什么 |
|---|---|---|
| **按团** | `groups[]` | 每个团的面貌 |
| **按创作者** ⭐ | `played_by` | **pd（KP）一个人扛了 69 个角色**；菌羊 32 / ReGMeoN 12 / 雪人 12 / 宽 11 / 往 9 |
| **按类型** | `tags[]` | PC / NPC / BOSS / 跨团 / KP |

**操作**：滚轮缩放 · 拖拽平移 · 双击空白复位 · 点卡片聚焦 · 再点开档案 · ESC / ◀ 返回。

## 四、技术要点（都是踩过的）

| 点 | 做法 | 为什么 |
|---|---|---|
| **布局确定性** | 不用力导向：小队 = 「按度数取种子 + 收邻居」，簇按行铺开 | 237 节点用力导向会抖、每次不一样，没法对照也没法截图 |
| **小队容量自适应** | `total>30 → 7 人/队`，`>14 → 6`，否则 4 | 固定 5 人时 48 人的团会切出 25 个小簇、铺成一根竖条 |
| **假 bloom** | 同一条线画两遍：宽半透明 halo + 细亮芯 | 比 SVG filter 便宜得多，观感几乎一样 |
| **卡片裁切** | 立绘按 2:3 居中偏上裁（保头），缩略 300px / 档案 620px | 卡片 120×180，档案要大图 |
| **`.hname` 选择器** | 队名标签挂在 `#labels` 下，**不是** `.hull` 的子元素 | 写成 `.hull .hname` 匹配不上 → div 退化成静态块全堆在原点（已踩） |
| **`node --check`** | 改完 JS 先 `node --check site\app.js` | 本机 Edge 截图在高内存压力下会崩，语法错会伪装成"截图失败" |
