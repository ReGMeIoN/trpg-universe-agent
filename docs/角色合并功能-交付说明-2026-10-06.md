# 角色合并功能（2026-10-06）

> 主人：「增加一个角色合并功能，有很多角色其实是同一个人，但是被一分为二了」。
> 已做成**编辑器里的一个按钮**：`🔗 合并`。以前这种活儿只能本小姐手工改数据（刘汤、林小元都干过），
> 现在谁都能点。

---

## 一、怎么用

1. 打开**要保留**的那个角色（入口：档案页「✎ 编辑这个角色」，或 `#/edit/<id>`）；
2. 点工具栏的 **`🔗 合并`** → 弹窗里**搜索/点选要被并进来的那个**（会列出每个候选的团与关系数）；
3. 弹窗会给出预览（"它会带着 N 条关系一起并入当前角色，然后消失"），点 **`合并进来`** 确认。

被并掉的那个角色随后消失；整个过程**进版本历史**（`kind=char_merge`），可在 `🕘 历史` 里一键回滚。

---

## 二、合并的语义（写清楚，免得以后搞混）

`src` = 被吃掉的；`dst` = 留下的（**保留它的 id / 主名字 / 立绘**）。

| 项 | 处理 |
|---|---|
| **关系** | 全部重定向 `src → dst`；重定向后与已有边 `(from,to,type)` 相同则去重；**合并后才出现的自环**（dst—dst）丢弃 |
| **重定向边 vs 原有边冲突** | **优先保留被合并方那条**（它的 `event` 常常写得更细），丢掉 dst 原来那条 |
| **别名** | 并集（并把 src 的**主名字**也加成别名，以后搜得到） |
| **出场团 / 系统标签** | 并集（跨团合并会把两边的团都留下） |
| **事件 events** | 按团合并、items 去重 |
| **属性 attrs** | 按维度合并，同维度值做字符串拼接 |
| **identity / note / profile** | **两份都留**：追加「—— 【简介·并入「X」】——」+ 原文 |
| **played_by / avatar** | 只在 dst 为空时继承 src 的（不乱覆盖） |
| **留痕** | dst 的 note 追加「【合并记录 日期】已并入 `<src id>`（名字）——关系重定向 N 处…」；并写 `merged_from: [src…]` |
| **权限** | **要口令**（合并是破坏性操作：会删掉一个节点） |

---

## 三、过程中抓到并修掉的两个真 bug（都在回归里现形）

1. **`dropped` 计数虚高、关系重定向数算重** —— 一条边的两个端点都指向 src 时被计了两次；
   真实案例：3 条边报了 `dropped: 5`。
2. **⚠️ 合并会误伤无关的边** —— 上一版对**整张关系表**做去重、并把**所有自环**都删了，
   结果把库里既有的 `g2_bimu → g2_bimu（一体同源）` 那条自环也吃掉了。
   修法：**只处理「端点涉及 src」的边**，其余边一根汗毛都不动（回归里加了数据一致性复核：
   合并前后与生产库逐边比对，零差异、零丢失）。

