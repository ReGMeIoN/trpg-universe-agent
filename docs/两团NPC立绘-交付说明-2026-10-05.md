## 二、知行：卡没坏，是工具坏了（本轮最值得记的一条）

`阴阳差事录-牛(1).docx` 的 `word/media/image1.png` 与 `image2.jpeg`，在 zip 的**中央目录里写的 CRC 是错的**，
于是 `zipfile.ZipFile.read()` 抛 `BadZipFile: Bad CRC-32 for file 'word/media/image2.jpeg'`。

上一轮据此判成「卡内图损坏 → 无立绘」。**实测是误判**：

```python
fp = z.open(name); fp._expected_crc = None; data = fp.read()   # 绕过 CRC 校验
# 解压长度 == 目录声明长度，PIL 能正常解码：
#   image2.jpeg  JPEG 1280×1280  → 就是知行的立绘（光头小和尚线稿，右下角有「豆包AI生成」水印）
#   image1.png   PNG  535×2064   → 与其他 PC 卡里同尺寸的模板底图
```

**修法**：给 `tools\_extract_sheet_images.py` 加 `read_zip_member_nocrc()`，
并在 `_extract_sheet_images.py` / `_cards_batch.py` 的 docx 分支上「CRC 不符 → 绕过校验重读一遍」。
重跑 `tools\_cards_batch.py` 后知行图正常抽出，再走既有的
`tools\_apply_portraits_new.py`（已加 `yy_zhixing` 一行）登记到 `数据\头像\`。

> **口径维持**：PC 严格用角色卡内原图 → 知行是 PC，所以**没有**给知行跑 NAI。

### 4.3 提示词写法（本轮修正了两个真问题）

1. **画师署名漏出**（实测复现）：画师串带 `artist:` 权重时，模型会把**署名**画在右下角
   （本次漏出过 `PATREON COMISITANGH / PRAGGTO KHINE ISIΠATTON ...` 三行英文）。
   NEG 里列再多 `signature/watermark` 都压不住 → 正解按 `trpg-gen21-pl.py` 的做法，
   在**正向串末尾**加正文负权重：
   ```
   SIG_KILL = -2::signature::, -2::watermark::, -2::artist name::, -2::text::,
              -2::patreon::, -2::copyright::, -2::english text::
   ```
2. **背景被压平**：原稿在构图串里写了 `simple background`，导致整批都是纯色底（难看）。
   改为**不写背景 tag**，背景交给各自的场景词 + 模型，观感接近 15/16 那两批 NPC 立绘。
3. **主串/角色栏分工**：沿用 gen21 的结构 —— 主串管 `1girl, solo + 构图 + anime illustration + 画师串 + SIG_KILL`，
   `v4_prompt.char_captions` 只管外貌（centers `[{'x':0.5,'y':0.45}]`）。

### 4.4 三档构图

| 候选 | 构图 |
|---|---|
| `a` | upper body, front view, looking at viewer |
| `b` | cowboy shot, three-quarter view |
| `c` | full body, dynamic pose, cinematic lighting |

seed 由 `md5("<角色id>|<候选字母>")` 派生 → **可重放**（同一角色同一候选永远同一 seed）。
