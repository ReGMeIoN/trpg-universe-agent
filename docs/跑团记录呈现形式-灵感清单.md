# 跑团记录还能怎么呈现 · 形式灵感与可行性清单

> 2026-10-04 整理。目的：**别再堆"又一页正文"**，而是找真正好吃、且现有素材能撑住的形式。
> 每条都标了「拿什么做」——能复用现成产物的排前面。

---

## 一、先说结论：本项目的独特优势

多数跑团记录站只有「文字 log」。我们手里有**四样大多数团队没有的东西**：

| 素材 | 现状 | 它能支撑什么 |
|---|---|---|
| **6.28 小时原始录音**（13662 转写段） | 已有，只剪了 15 段 26 秒 | **原声对读**、有声书、口癖统计 |
| **逐段剧情编年史**（3.07 万字） | 已有，且已清洗成读者口径 | 漫画分镜、剧本、时间轴的唯一文本源 |
| **5 名 PC 的外貌锚点表** | `novelai\pc_looks.py` | **角色一致性**是漫画化的前提，我们已解决 |
| **NAI V5 多角色可控出图 + 卡面立绘** | 已验证（PC 版 15 场景） | 分格漫画、立绘表情差分 |

**所以真正该押注的方向是「把文字变成画面/声音」，而不是再换个排版。**

## 二、搜索结果里的现成做法（可借鉴）

### A. 日式「リプレイ本」（最成熟的一支）

- [Replay Book Maker](https://booth.pm/ko/items/8775734)：把 cocofolia 的跑团 log 直接**排成可印刷的 PDF 同人志**（入稿用）。
- [おもいでログ](https://booth.pm/ko/items/8504409)：把 session log 排成"好看的 log + 统计"。
- [リプレイ的書式讨论](https://trpgsession.com/player/leafwoodts00/comment/leafwoodts00_172640020998/)：日式 replay 的典型结构＝
  **章节 + 台词体 + 旁白框 + 插画彩页**，读起来像轻小说。

→ **可直接抄的形态**：把编年史排成"**台词体 replay**"（谁说了什么用引号顶格），
配少量彩页插画，导出 A5 PDF 当同人志。**我们已有全部文本与插画素材。**

### B. 战役 wiki / 记忆库

- [Obsidian Portal 及同类](https://paizo.com/threads/rzs2rq8r?Obsidian-Portal-similar-sites)：战役 wiki，人物页 + 地点页 + 时间轴。
- [Chronicle Keeper 的 views](https://aronjanosch.github.io/chronicle-keeper/docs/views.html)：**Maps / Timeline / Graph** 三种视图。
- [obsidian-icewind](https://github.com/shervinsahba/obsidian-icewind)：用 zettelkasten 组织一场战役。
- [Table Canon（HN）](https://app.hncompanion.com/item?id=49376991)：AI 战役记忆引擎——**问它"上次那个 NPC 叫啥"**。

→ 我们已有 `characters/relations` 数据 + 关系图。缺的是**地点页**与**可提问的检索**。

### C. 漫画 / 分镜（AI 化最热的一支）

- [Campaign Recap Comics](https://comistitch.com/blog/campaign-recap-comics-for-your-table/)：把每次 session 画成**回顾漫画**，维持桌面黏性。
- [aimangastudio](https://github.com/morsoli/aimangastudio)：脚本 → 分镜 → 角色风格控制的 AI 漫画工具链。
- [Comfyui-Yumi-Comics](https://github.com/Everytimeyumi/Comfyui-Yumi-Comics) / [easydraw](https://github.com/Coldplay-now/easydraw)：ComfyUI 系的漫画流水线。
- [D&D 跑团可视化](https://texttomanga.com/zh/blog/dnd-character-visualizer)：角色可视化侧重。

→ **这是最有想象空间的一条，而且我们的素材最齐**（文本 + PC 外貌锚点 + 多角色出图能力）。

### D. 有声 / 配音

- [TextToSpeech-MoeGoeGUI](https://github.com/ffftian/TextToSpeech-MoeGoeGUI)：文本 → 音频的本地配音工具。

→ 我们**有真人原声**，不需要 TTS 扮演角色；TTS 只适合做"旁白朗读"。

## 三、八个具体方案（按"性价比"排序）

### ★★★ 1. 分格漫画（最推荐）

**形态**：每小节 → 3~4 格漫画页，有**对话框、旁白框、拟声词**。像日式 replay 的彩页。

**为什么我们做得成**：
- 文本：编年史已按小节切好（78 节），每节自带起承转合；
- 画面：`pc_looks.py` 的锚点 + NAI V5 的 `char_captions` + `centers` 定位，
  已实测能稳定出"两个指定 PC 同框"；
- **对话框不靠 AI 画**（AI 画中文字必崩），而是**HTML/CSS 叠在图上**——可改、可搜、可选中。

**工序**（每小节）：
1. LLM 把该节正文 → 分镜表（每格：谁在场 / 动作 / 表情 / 镜头 / 台词 / 旁白）；
2. NAI 出每格底图（无文字，`no text`）；
3. 前端按分镜表摆格子 + 叠气泡。

**工作量**：管线约 1 天；78 节 × 3~4 格 ≈ 250~300 张图，按免费档每张 ~9 秒 ≈ **40 分钟出图**（分批跑）。

**风险**：多格连续性的服装/发型一致性——靠角色栏锚点 + 同一 seed 微调可缓解；
实在不行就"每格只 1~2 人 + 特写为主"，规避全身多角色。

---

### ★★★ 2. 场景地图 / 旅程图（视觉冲击最大）

**形态**：一张**大陆地图**，把三国十一个国度、走过的路线、关键事件点标上去；
点一个点 → 弹出那一节的小卡（CG + 一句梗概 + 原声）。

**为什么我们做得成**：编年史里地点很清楚（雷之国、光之教皇国、海底教人族、雪人故国、
矮人国、虚空圣殿、亡云村庄…），路线是线性的（段1→段6 就是一条路）。

**产出**：1 张手绘风地图（NAI 或矢量重绘）+ 事件点数据 JSON。

**工作量**：地图 0.5 天（出图多试几张），接线 0.5 天。

---

### ★★★ 3. 原声对读（**本项目独一份**）

**形态**：**左**＝清洗后的编年史正文（可读），**右**＝同一时间点的**原始录音转写**（带错字、口癖）。
点播放 → 听到桌面上的真实状况；鼠标移到某段 → 高亮录音里对应位置。

**为什么独一份**：这是**"跑团记录"到"成品"的差距本身**——
只有既留了 6.28 小时录音、又做了 AI 提炼的项目才能做这个对读。
它比任何华丽排版都更能体现"这东西是怎么来的"。

**素材**：`素材\圣剑英雄谭.mp3`（6.28h）+ 转写（13662 段）+ 编年史时间戳。
**注意**：编年史里存了 `[4061.98-4062.98]` 这种时间戳引用（站点版清洗时删了），
**内部版还留着** → 正好用来做对齐。

**工作量**：对齐 0.5~1 天（时间戳已在文本里，解析即可）。

---

### ★★ 4. 时间轴 / 旅程视图

**形态**：横轴＝6h16m 的真实时间，纵轴＝小节；鼠标划过出缩略 CG 与梗概；
**PC 泳道**：每个 PC 一条线，标出他在哪几节是主角（"谁的高光在哪"）。

**为什么值得**：我们已经有每节的时间戳与小节划分，**纯数据活**，一天能做完，且很有"考据感"。

**彩蛋**：可以标出"骰子转折点"——编年史里凡出现"困难敏捷判定成功""大成功"的地方。

---

### ★★ 5. 关系网络**随剧情演化**（把已有关系图升级）

**形态**：现在的关系图是**静态结局态**。改成**时间轴滑块**：
拉到段1 → 只显示段1 已建立的关系（皇帝对宽＝委托/被拒绝）；
拉到段6 → 才出现"新四骑士""世界修正"。

**为什么值得**：`relations` 每条都带 `event` 与出处（如"段1 [18:41]-[25:52]"），
**演化数据已经在库里**，不用新造。做出来是"人际关系的动态史"，比静态图强一个量级。

**工作量**：1 天（解析出处 → 按段聚合 → 滑块重绘）。

---

### ★★ 6. 立绘表情差分 / 角色卡

**形态**：每个 PC 一张"表情差分表"（认真 / 笑 / 怒 / 醉 / 受伤），
做出**人物设定集**那一页的感觉。

**还原度提示**：卡面给了大量行为特征——八重樱「武痴、酗酒」，
妮娜「空洞无感情、笨拙地模仿笑容」，流星亚什「天然呆」，
飒飒米「事不关己的旁观者」。表情差分能把这些**演出来**。

**工作量**：5 人 × 6 表情 = 30 张（NAI 免费档 ~5 分钟出完），排版 0.5 天。

---

### ★ 7. 剧本 / 台词本（replay 排版）

**形态**：把编年史排成日式 replay 的**台词体**：

```
宽（八重樱）：「你说这些，我都不想要。想要我做事，只有我认可的人。」
　　　　—— 段1 · 大殿接见 [18:41]
```

导出**可打印 PDF**（A5，双栏，配彩页插画）。可以做实体同人志。

**工作量**：排版工具半天；文本已有。

---

### ★ 8. 有声书 / 音频剧

**形态**：把编年史朗读成音频（旁白＝TTS，角色台词＝真人原声混剪）。

**诚实评价**：**性价比最低**。我们有真人原声，让 TTS 去"演"PC 只会更难听；
混剪对齐的工作量又很大。**建议只做"关键场景旁白"少量点缀**，不做全篇。

---

## 四、如果只做一件

**分格漫画**（★★★1）。

理由：它把本项目**全部四样独特素材**都用上（文本 / 外貌锚点 / 出图能力 / 原声可插格），
且是所有形式里**信息密度与冲击力最高**的。日式 replay 文化证明了这个形态成立，
而我们比传统 replay 多了"AI 可控出图"这一环——**过去是因为画不起才用文字**，现在画得起了。

**次选**：原声对读（★★★3）——它是"别人抄不走"的那一个。
